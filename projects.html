Lost Items Management System (LIMS)

Helps a campus community report, match, and recover lost belongings without relying on a manual, walk-in lost-and-found desk.

LIMS is a full-stack web platform built for my final-year Computer Science project at Hawassa University, where a paper-based lost-and-found process made it slow and unreliable to reunite people with their belongings. Users can report a lost or found item, search existing listings, and get flagged as a likely match when a report on the other side lines up. I led a small team and owned the backend: the MySQL data model, the matching logic, and the REST API that the React frontend runs on.

Technologies

  • HTML
  • CSS
  • JavaScript
  • React
  • Node.js
  • MySQL
  • Git
  • GitHub

Key features

  • Guided reporting flow for both lost and found items, with category, location, and photo details
  • Keyword and category search across all open listings
  • Matching logic that compares new reports against existing ones and surfaces likely pairs for review
  • REST API (Node.js) connecting the React frontend to a normalized MySQL schema
  • Role-based team workflow: I owned the backend and API contract while teammates built the frontend against it

The challenge

The hard part was not the CRUD screens, it was the matching logic: designing a MySQL schema that could reliably pair a "lost" report with a "found" report without turning into a slow, manual review queue, while three teammates were building against my API at the same time.

What I learned

Agreeing on the API contract early — exact request and response shapes — mattered more than any single line of backend code. Once that was locked in, the React and backend halves of the project could move in parallel instead of blocking each other.
